# 智能厨房管家 Agent Demo

浏览器运行的本地 Web Demo，包含首页、冰箱库存、菜谱和采购清单。

## 本地预览

```sh
ruby server.rb
```

打开 <http://127.0.0.1:4567>。库存、偏好、菜单、菜谱草稿、我的菜谱和做饭进度保存到本机 `data.json`；没有账户同步能力，不支持跨设备同步。不要将个人数据或密钥提交到仓库。

## 菜谱体验

- 「吃什么」从 `assets/recipes.json` 读取 180 道菜谱，通过菜名或食材搜索。「现有食材」要求主要食材在冰箱有可用记录，数量不足时仍可推荐并提示补购，「不限食材」跨餐次与用时从整份菜谱库随机挑选，也支持输入菜名或食材搜索；两者都遵守人数缩放、过敏、忌口和厨具限制。「换一批」优先显示未看过的符合条件菜谱。
- 菜谱推荐、图片搜索、正文 AI 解析和 AI 封面接口已停用。分享链接和手动上传封面继续保存在「我的菜谱」。
- 首页提问、发现需求、我的菜谱检索、冰箱食材检索、添加库存和快速添加采购均可使用统一语音控件。语音通过浏览器 Web Speech API 识别，权限、支持情况取决于浏览器；应用不上传或保存录音，浏览器语音服务可能按自身规则处理音频。识别后可编辑、追加或替换，需用户手动提交。
- “我的菜谱”支持保存、搜索和编辑。可给分享链接填写菜名并上传封面，与收藏的推荐一起显示在「我的菜谱」，点卡片打开原平台。粘贴正文可保存为草稿，手动填写食材和步骤。截图可随草稿保存。
- 本餐可添加多道菜。制作页按菜品展示完整流程图，左右滑动查看各道菜；制作中可返回发现和我的菜谱继续选菜。点击「制作完成」后进入食材用量确认。
- 做完后直接查看食材用量清单。冰箱食材默认按参考量扣减，可在原行修改数量或来源。清单标明食材来源。外购和来源待确认的食材选「有剩余」即可填写实际数量，再决定是否入库。暂不入库时也能记录数量。「稍后再记」保存待确认进度。确认后才扣减旧库存、记录外购消耗和补记剩余。
- 预设菜谱分列主要食材、辅料和调味料；原文未提供的基础调味项只作为可编辑的“建议补充”，并标记适量/未知，不换算成精确用量。单位不兼容或数量不确定时不计算精确缺口。

## 菜谱库与图片

`assets/recipes.json` 是用户提供的菜谱库原文件，180 道均标记午餐、晚餐，其中 5 道也标记早餐，未标记宵夜。菜谱配图从用户提供的「家常菜单（示例）.xlsx」按同一行菜名与图片锚点匹配提取，图片压缩后随项目存放。图片来源中保留工作表和单元格，原始授权未注明。没有当前餐次或条件下的候选时如实显示空结果。

## 开发与验证

测试或并行预览时可将 `DATA_PATH` 指向临时 JSON 文件，并用 `PORT` 指定端口；默认仍使用项目根目录的 `data.json`。例如：

```sh
DATA_PATH=/tmp/demo5018-recipe-test.json PORT=4568 ruby server.rb
```

## 其他能力

首页自由问答可单独配置 DeepSeek。复制 `.env.example` 为 `.env` 并填写服务端 API Key；密钥只保存在服务端环境，不应写入前端资源。未配置时不影响本地菜谱流程。

AI 食材录入在用户确认识别结果后，会把正式知识库尚未包含的标准名称、别名、分类、单位克数和默认储存方式写入 `food_knowledge_supplement.json`。读取时采用“正式知识库优先、补充库只填缺失信息”的合并规则；已有正式字段不会被 AI 覆盖。本次库存数量、存入日期和当前新鲜度不会作为通用知识保存。当前确认过的补充食材会随仓库同步，后续变更提交前应检查其中不包含个人信息。

## 当前菜谱分支预览

请从本目录运行 `zsh ./预览菜谱分支.command`，然后打开 <http://127.0.0.1:4570>。脚本只会停止已核实运行在原 Copilot 工作目录的旧 4570 预览；若端口由其他目录占用，会报错退出。旧目录文件不会删除。新预览使用独立示例库存，不修改 `data.json`；访问 <http://127.0.0.1:4570/api/status>，应看到 `service: demo5018-recipe`、`branch: moonxiang1222-recipe`、`isolatedData: true`。操作变化、验证结果与尚未完成的页面验收见 [菜谱体验调整](docs/recipe-ui-adjustments.md)。图片生成依用户最新要求暂缓，等待后续接入图片API。

本地菜谱整合分支基于主干 `5ece0a1`（2026-11-15 核对远端）。首页、冰箱、我的和原采购页沿用主干 `app.js` / `styles.css`；菜谱功能迁至独立的 `recipe-app.js` / `recipe-styles.css`，通过 `recipe-host.js` 接入。共享数据仍保存在同一个 DATA_PATH，使用版本号和库存快照防止互相覆盖。整合不修改远端或本地 main，也不自动推送。详情与验收记录见 [主干兼容整合](docs/recipe-main-compatibility.md)。

## 回归检查

```sh
node tests/client_test.cjs
node tests/recipe-integration.test.cjs
node tests/homepage-scope.test.cjs
ruby tests/server_test.rb
```

菜谱前端修改请编辑 recipe-app.js / recipe-styles.css；不要把菜谱的全局选择器或事件处理器放回主干 app.js / styles.css。

菜谱卡片内、菜名正下方展示菜系（川菜、湘菜、粤菜等）与特点（时令菜、快手菜、少步骤）标签，仅作为信息展示，不提供独立分类筛选区，也不限制推荐结果。时令标签按浏览器本地月份与主要食材的常见采收季节参考判断，地区、设施种植等会造成差异，不代表当地实时供应。参考资料：[上海市农业农村委员会](https://nyncw.sh.gov.cn/bwbdzzl/20190123/0009-113018.html)、[央视时令蔬菜介绍](https://news.cntv.cn/20120123/119576.shtml)、[十一月产地上市参考](https://chisha.taoliapp.com/m/11)。
